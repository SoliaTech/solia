# Solia RFC 0003 · 类型化 AI 任务与声明式 2D 场景

| 项目 | 内容 |
| --- | --- |
| 状态 | 首版已实现；下文保留设计依据 |
| 实施仓库 | `solia` 提供语言、绘制和任务运行时；`solia-browser` 提供来源、授权和实例生命周期 |

## 1. 第一次演示

打开一张星图。用户用滑块移动蓝色基地，然后点击“建议观测点”。模型读取基地坐标，返回一个橙色观测点的位置。用户可在模型计算期间继续操作；如果基地已经移动，旧建议不会覆盖当前场景。用鼠标或键盘改变滑块，即使没有配置模型也能验证绘制和状态绑定。

这个例子给两项能力设定了独立验收线。2D 可以用已有状态和控件运行；AI 可以先把结果写回状态并通过普通 Text 显示。两端联通后，同一份源码无需专用的“AI 绘图”组件。

## 2. 作者如何编写应用

以下示例使用当前编译器支持的语法。整数状态同时驱动滑块、图元和提示词；模型输出通过字段声明绑定到目标状态。

```solia
app StarMap {
    capabilities { ai.infer }

    state {
        base_x = 80
        base_y = 90
        star_x = 240
        star_y = 90
    }

    task suggest {
        prompt: "在 320×180 的星图上选一个远离基地 ({base_x}, {base_y}) 的观测点。"
        output {
            x: i32(min: 8, max: 312) -> star_x
            y: i32(min: 8, max: 172) -> star_y
        }
    }

    view {
        Column(gap: 12) {
            Scene2D("星图", width: 320, height: 180, background: "#101828") {
                Rect(x: 8, y: 8, width: 304, height: 164, fill: "#20304A")
                Circle(x: base_x, y: base_y, radius: 6, fill: "#58A6FF")
                Circle(x: star_x, y: star_y, radius: 8, fill: "#FFB35C")
            }
            Slider("基地 X", value: base_x, min: 8, max: 312)
            Slider("基地 Y", value: base_y, min: 8, max: 172)
            Button("建议观测点") { run suggest }
            Text("基地 ({base_x}, {base_y}) · 观测点 ({star_x}, {star_y})")
        }
    }
}
```

`task` 位于 state 与 view 之间，任务名在应用内唯一。prompt 是支持现有状态插值的字符串。输出字段名唯一，目标必须是不同的、已声明的同类型状态槽。首版接受带闭区间的 `i32` 和 `bool`；整数上下界是编译期常量。编译器在调用点检查任务名和能力声明。首版 `run` 仅允许作为按钮的唯一语句，这样一次激活动作对应一次可辨认的模型请求。

## 3. 2D 绘制契约

| 项目 | 首版规则 |
| --- | --- |
| 画布与布局 | `Scene2D` 可嵌于 Row 或 Column。宽高为 1–4096 的正整数常量。以声明尺寸为首选大小，可用宽度较小时等比缩小，高度随之变化。 |
| 坐标 | 左上为原点，x 向右、y 向下。矩形以左上角定位，圆以圆心定位。变换以逻辑单位计算，由宿主处理屏幕像素密度。 |
| 形状 | `Rect` 与 `Circle` 按源码顺序绘制，后面的覆盖前面的。几何参数可用整数常量或 `i32` 状态名。颜色为编译期 `#RRGGBB`。 |
| 边界 | 所有图元裁剪到画布与父内容区的交集。负坐标可表达局部越界；常量尺寸或半径小于零应报错，动态值小于等于零时跳过该图元。先转为有界浮点坐标再做几何运算，避免整数相加溢出。 |
| 交互与可访问性 | 首版通过已有按钮和滑块控制场景。画布在语义树中暴露其标签，示例用文本表达坐标，键盘可完成同一操作。 |
| 重绘与预算 | 控件输入及任务完成时请求重绘。复用现有 egui 绘制区域和 painter，图元直接读取同一实例的状态；建议每个场景最多 1024 个图元，图元也计入现有 4096 节点总限额。 |

动画、精灵和场景内命中测试可分别增量加入。第二批优先加入点击选点：对指针执行与绘制互逆的坐标变换，先检验高 DPI 和缩放后的命中位置，再考虑逐帧模拟。

## 4. AI 请求、授权与状态提交

1. **触发。** 用户激活按钮时，运行时展开提示词，保存其引用的状态槽和输出目标槽的当前值。每实例最多一个活动请求。
2. **授权。** Browser 在应用内容区之外显示最终来源、实际配置的模型服务、待发送文本，以及“允许本次”和“取消”。重定向时采用下载完成后的来源。CLI 使用同一宿主对话框，来源显示为当前打开的本地文件。在用户允许前，模型服务收到的请求数应为零。UI 的重新绘制不能触发推理。
3. **推理。** 宿主将不可变请求交给异步 provider。应用只声明任务，模型、服务地址和凭据由用户在宿主配置。宿主按任务声明提供输出约束，并在收到响应后校验字段。
4. **校验。** 接收一个完整 JSON 对象，字段完整且唯一，拒绝额外字段、错误类型和越界整数。模型只获得展开的 prompt 和输出约束。响应通过字段名映射到编译时绑定的目标槽；响应中的文字不作为 Solia 源码、路径或工具调用解释。
5. **提交。** 按钮处理器和控件事件执行后，宿主用当前值核对快照。若相关状态已改变，宿主取消请求并丢弃其结果接收端。全部校验通过后，在同一次更新中提交全部目标槽并重绘。加载时预验证槽类型与可变性，提交前准备好全部值，以免界面看到更新了一半的坐标。
6. **取消与失败。** 等待授权、推理中、完成、取消、超时和失败由宿主显示。请求进行时提供取消操作。实例被替换或关闭时释放该实例的请求及结果接收端；导航失败而旧实例仍在运行时保留其状态。未配置模型时给出配置入口。授权拒绝、超时及无效结果都保留原状态；重试由用户触发。

宿主限制展开后的 prompt 为 4 KiB，整个 HTTP 响应正文为 16 KiB，每任务最多 16 个输出字段，请求超时为 30 秒。

## 5. 编译器、包与宿主接口

| 层 | 设计改动 |
| --- | --- |
| 编译器 | 扩展几何参数为常量或已解析状态槽；任务 IR 包含 prompt 片段、输出字段、区间、目标槽和读写集合。用有区别的按钮动作表示现有同步处理器和请求任务。 |
| SAPP | 新能力进入 v3。清单新增能力集合、任务表、场景和图元节点。加载器独立检查节点预算、引用、输出槽、可变性、参数类型和能力匹配。旧程序按现有规则继续生成 v1/v2，新宿主同时读取三版。 |
| Solia 运行时 | 保留 WASM 状态和现有按钮 ABI。请求任务是宿主识别的按钮动作，通过已验证清单生成；WASM 不获得网络导入。控件或按钮处理器修改状态后，宿主检查待处理请求的快照。 |
| 共享 AI 接口 | 运行时对外产生待批准的请求；宿主可批准、取消，并通过该请求专属的通道接收完成事件。provider 仅依赖 prompt、schema、取消信号和预算，不持有 UI 或 WASM Store。CLI 与 Browser 共用适配器和结果验证。 |
| 浏览器及 CLI | 负责配置、可信来源展示和授权 UI。模型请求独立于 Browser 的源码下载线程，完成时唤醒窗口。Browser 成功换页时销毁旧实例的任务作用域。 |

## 6. 分期交付与验收

| 里程碑 | 交付与可重复验收 |
| --- | --- |
| A · 2D 独立运行 | CLI 与 Browser 打开纯 2D 场景。滑块移动圆心；用几何断言验证窄窗口下的坐标、矩形与圆的遮挡顺序、越界裁剪；已有 Counter 和 Settings 包继续运行。 |
| B · AI 契约 | 单独运行把结构化结果显示为 Text 的应用。确定性 provider 分别返回合法坐标、缺字段、重复字段、越界值和延迟响应。验证只有合法响应会一次性更新两个槽；拒绝时计数为零；新实例不接收旧结果。 |
| C · 真实推理与联验 | 配置一个已有的本机模型，分别从 CLI 和测试域名打开星图。用户授权一次，真实服务收到一次请求，合法结果同时改变文本与橙点。推理中拖动基地、取消或重载，验证迟到结果不能覆盖用户的新状态。未启动模型时 2D 和已加载应用仍可操作。 |

测试源站已发布星图。[打开示例源码](https://solia.home.rethinkos.com/star-map.solia)

进入下一阶段的依据是上述行为在两种宿主均可重现，而非特定模型每次生成相同坐标。后续 AI 能力优先评估自由文本输入、流式文本和工具调用；三者分别需要字符串状态与 IME、增量输出语义，以及独立的工具权限契约。

## 7. 运行与验证

在 `solia` 仓库执行 `cargo run --locked -- run examples/star-map.solia`，或在 Solia Browser 地址栏打开上面的 HTTPS 示例。拖动 **Base X / Base Y** 即可观察蓝色基地移动。点击 **Suggest a star**，确认应用来源、目标网关、模型和提示词，再点 **Allow once**。响应通过校验后，坐标文本和橙色观测点会一起更新。

CLI 与 Browser 在加载应用时读取同一套 AI 配置。修改配置后重新加载应用，再发起请求。验收时检查坐标文本与橙色观测点是否同步更新，并确认取消请求后原坐标保持不变。[运行说明](../README.md#2d-scenes-and-ai-inference)
