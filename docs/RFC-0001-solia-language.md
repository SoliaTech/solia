| 项目 | 内容 |

| 状态 | 草案，征求项目评审 |

## 摘要

一个 Solia 源文件定义一个应用。作者在 `state` 中声明数据，在 `view` 中描述控件如何显示这些数据，在按钮处理器中更新数据。本文规定编译器应接受哪些程序，以及用户激活控件后应看到什么结果。

## 1. 动机与规范用语

同一个计数器从源码运行或从应用包启动时，应有相同的初始值、运算结果和界面文字。为此，类型检查、整数溢出、事件执行顺序和文本插值都需要明确的规则。编译器的中间表示、窗口工具包和包的字节布局属于实现细节。

第 2 至 7 节定义语言规则。大写 **MUST** 表示强制要求，**MAY** 表示允许的实现选择。仅大写英文关键词具有 BCP 14 定义的规范含义。[RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) · [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174)

## 2. 源文件与词法

- 源文件采用 UTF-8。标识符区分大小写，匹配 ASCII 正则表达式 `[A-Za-z_][A-Za-z0-9_]*`。词法分析按最长连续标识符取词，例如 `state1` 是一个名字。
- 字符串外的 Unicode 空白分隔词元。两个连续的斜杠 `//` 开始行注释，延续至 LF 或文件末尾。换行与缩进没有分块作用，大括号确定块的范围。
- 十进制数字串由一个或多个 ASCII 数字组成，允许前导零。`-` 是独立词元，在整数前表示负号。整数必须落在 −2147483648 至 2147483647 的闭区间。超出范围的字面量在编译时出错。
- 字符串由双引号包围，可以为空。字符串内部允许 Unicode 文本和下表中的转义。未转义的双引号结束字符串，原始 LF、未闭合字符串及未定义的转义均为词法错误。

| 源码中的转义 | 解码结果 |
| --- | --- |
| `\"` | 双引号 |
| `\\` | 一个反斜杠 |
| `\n` | 一个换行符 LF |

## 3. 语法

下列 EBNF 中，引号表示源码词元，空格表示连接，竖线表示选择，方括号表示可选，花括号表示重复零次或多次。每行定义一个产生式。`Identifier`、`Digits` 和 `String` 分别对应第 2 节的标识符、数字串和字符串。`EOF` 表示文件结束。

```ebnf
File         = "app" Identifier "{" [ Config ] [ State ] View "}" EOF
Config       = "config" "{" { Property } "}"
Property     = "title" ":" String
             | "window" ":" "(" Integer "," Integer ")"
             | "theme" ":" ( "dark" | "light" )
State        = "state" "{" { Declaration } "}"
Declaration  = Identifier [ ":" Type ] "=" Literal
Type         = "i32" | "bool"
Literal      = Integer | "true" | "false"
Integer      = [ "-" ] Digits
View         = "view" "{" Column "}"
Column       = "Column" [ "(" "gap" ":" Integer ")" ] "{" { Widget } "}"
Widget       = "Text" "(" String ")"
             | "Button" "(" String ")" "{" { Assignment } "}"
Assignment   = Identifier Operator Operand
Operator     = "=" | "+" "=" | "-" "="
Operand      = Literal | Identifier
```

文件中恰有一个 `app`。各块按 `config`、`state`、`view` 的顺序出现，前两块可以省略。`view` 必须包含一个根列，列可为空。词元序列决定声明和语句的边界，因此同一行可以写多条赋值。分号不属于语法。`+=` 和 `-=` 中的两个符号之间允许空白。

## 4. 窗口与视图

| 设置 | 允许值 | 省略时 |
| --- | --- | --- |
| `config.title` | 字符串，按解码后的原文显示 | 应用名 |
| `config.window` | `(宽, 高)`，每项为 1 至 8192 的整数 | `(640, 480)` |
| `config.theme` | `dark` 或 `light` | `light` |
| `Column(gap: …)` | 0 至 8192 的整数 | `8` |

配置项可按任意顺序书写，每项最多一次。编译器 **MUST** 拒绝未知配置项、重复项及越界尺寸。窗口尺寸表示期望的初始内容区大小，尺寸与间距均以界面逻辑单位计。桌面环境可以约束实际窗口大小。

`Column` 按源码顺序从上到下放置子控件；`gap` 指相邻控件之间的垂直间距。`Text` 显示标签，`Button` 显示标签并绑定自己的处理器。按钮的处理器块可以为空。

## 5. 状态、名称与类型

同一应用实例中的所有控件和处理器共享一个状态作用域。状态名必须唯一。`true` 和 `false` 在操作数位置表示布尔常量，禁止用作状态名。其余语法词按上下文识别，例如 `state { view = 1 }` 中的 `view` 是合法状态名。标签引用、赋值目标和右侧的状态引用都必须在编译时解析到该作用域内的声明。

| 状态类型 | 初值 | 普通赋值 | 复合赋值 |
| --- | --- | --- | --- |
| `i32` | 有符号 32 位整数字面量 | 同类型字面量或状态值 | `+=`、`-=`，右侧须为 `i32` |
| `bool` | `true` 或 `false` | 同类型字面量或状态值 | 禁止 |

每个声明都必须给出字面量初值。省略类型标注时，编译器从该字面量推断类型；给出标注时，两种类型必须一致。状态的类型在整个实例生命周期内固定。编译器 **MUST** 拒绝隐式整数与布尔值转换，例如 `ready: bool = 1`。字符串仅出现在窗口标题与控件标签位置。

## 6. 执行与插值

1. **实例化。** 每次启动应用时，宿主 **MUST** 用声明的初值创建独立状态。首次渲染读取这些初值。
2. **按钮激活。** 宿主执行对应的处理器一次。处理器逐条执行语句，每条语句先读取操作数，再写入目标。后一条语句可以读取前一条刚写入的值。
3. **算术。** `x += y` 和 `x -= y` 分别计算加法和减法。结果按模 2³² 回绕，再解释为有符号整数。因此，合法状态值 `2147483647` 加一后得到 `-2147483648`。
4. **重绘。** 处理器正常结束后，下一次绘制的标签 **MUST** 反映更新后的状态。宿主 **MAY** 缓存标签，只要可观察的结果相同。

标签先解码字符串转义，再解析 `{名称}`。花括号内必须恰好是已声明状态的名字；空格、空名称以及表达式（如 `{x + 1}`）均会导致编译错误。标签中每个花括号都参与插值语法，当前没有显示字面花括号的转义写法。窗口标题只做字符串解码，因此标题 `"{x}"` 会原样显示三个字符。

插值按出现顺序拼接文字和值。整数采用十进制有符号表示，如 `-4`、`0`、`12`；布尔值显示为小写 `true` 或 `false`。同一个状态可以在同一标签内出现多次。

## 7. 诊断

编译器 **MUST** 在运行前拒绝违反词法、语法、名称解析或类型规则的程序。源码诊断包含文件位置，行号和列号从 1 开始。当前实现以 LF 换行，按 Unicode 标量值计算列号。错误措辞可以因实现而异。

| 无效片段 | 所在位置 | 拒绝原因 |
| --- | --- | --- |
| `count = 2147483648` | 状态声明 | 初值超出 `i32` 范围 |
| `copy = count` | 状态声明 | 初值必须是字面量；同类型状态间的复制可写在处理器中 |
| `ready += true` | 按钮处理器，`ready: bool` | 布尔类型不支持加法 |
| `Text("{missing}")` | 视图，未声明 `missing` | 插值引用无法解析 |
| `window: (640, 0)` | 配置块 | 高度小于 1 |

## 8. 一致性示例

以下程序用一次按钮激活同时检验整数边界、赋值顺序和标签更新。

```solia
app Boundary {
    state {
        value: i32 = 2147483647
        last = 0
        touched = false
    }
    view {
        Column {
            Text("{last} → {value}")
            Button("Touched: {touched}") {
                last = value
                value += 1
                touched = true
            }
        }
    }
}
```

| 观察时刻 | 文本 | 按钮标签 |
| --- | --- | --- |
| 初次显示 | `0 → 2147483647` | `Touched: false` |
| 第一次激活后 | `2147483647 → -2147483648` | `Touched: true` |
| 第二次激活后 | `-2147483648 → -2147483647` | `Touched: true` |

仓库还提供一个可直接运行的计数器。执行 `cargo run -- run examples/counter.solia`，每次激活 **Increment**，显示值增加 1。[Counter 源码](../examples/counter.solia)

## 9. 安全与宿主边界

该子集的处理器只读写实例状态。标签插值只读取编译时绑定的状态名，文字内容按文本渲染。当前 Rust 宿主以空导入集装载 WebAssembly 模块，为每次按钮处理设置执行预算，并在打开窗口前检查包版本、状态引用及导出类型。宿主报告包加载错误或执行预算耗尽，与第 7 节的源码诊断分别处理。[包加载校验](../src/package.rs) · [宿主实现](../src/host.rs)

## 10. 兼容性与待决问题

本草案以 0.1.0 实现为基线。以下问题供后续 RFC 讨论，会影响现有程序的解释或需要新的语法。

- 引入模块和函数后，状态名能否被局部变量遮蔽？现行规则对每次引用都能确定唯一的应用状态。
- 标签如何显示字面花括号？例如 `"{{x}}"` 在本版会被拒绝；为这一写法赋予含义可以扩展可接受的程序集合。
- 增加算术表达式时，优先级、求值顺序及中间结果的溢出规则如何与已有复合赋值保持一致？

语言文法与应用包格式独立演进。包头中的版本号用于宿主兼容性检查。源语言的变更应说明对现有 `.solia` 程序的影响。[项目路线图](../README.md#roadmap)
