# Solia RFC 0002 · 布局与基础交互组件

| 项目 | 内容 |
| --- | --- |
| 状态 | 设计草案，待评审 |
| 扩展规范 | [RFC 0001 · 单文件应用语言](RFC-0001-solia-language.md) |
| 适用端 | Solia CLI 原生窗口、Solia Browser 应用内容区 |

## 1. 用户场景

希望作者能写出一个可操作的设置面板：横向排列标题和数值、勾选静音、用滑块调整音量、用按钮恢复默认值。这个例子可以验证嵌套布局、两种类型的输入、多个控件共享状态，以及从 HTTPS 打开后的完整交互。这里的音量只是应用内数字，不涉及音频设备。

以下是提议的完整源码，可在实现后作为 `settings.solia` 验收。

```solia
app Settings {
    state {
        muted: bool = false
        volume: i32 = 40
    }

    view {
        Column(gap: 12) {
            Heading("Audio settings")
            Checkbox("Mute", checked: muted)
            Row(gap: 8) {
                Text("Volume")
                Text("{volume}%")
            }
            Slider("Volume", value: volume, min: 0, max: 100)
            Divider()
            Row(gap: 8) {
                Button("Reset") {
                    muted = false
                    volume = 40
                }
                Text("Muted: {muted}")
            }
        }
    }
}
```

## 2. 组件与语义

| 组件 | 参数与子节点 | 布局或状态行为 |
| --- | --- | --- |
| `Column` | 可选 `gap`，可含任意组件 | 从上到下排列，支持嵌套 |
| `Row` | 同 `Column` | 按源码顺序横排，宽度不足时在子组件之间换行 |
| `Heading` | 一个标签 | 使用宿主标题样式，向辅助技术暴露标题语义 |
| `Divider()` | 无参数 | 沿所在布局的交叉轴分隔相邻内容；列内为水平线，行内为垂直线 |
| `Checkbox` | 标签、`checked: 状态名` | 绑定 `bool`；用户激活一次，提交一次新的布尔值 |
| `Slider` | 标签、`value: 状态名`、`min`、`max` | 绑定 `i32`；上下界都是整数常量，端点可取，步长为 1 |

`Column` 和 `Row` 均可作为唯一根节点。每个容器的 `gap` 默认值为 8，范围沿用 0 至 8192，仅决定直接子节点在主轴上的间距。作者可以用空容器组织视图。现有 `Text`、`Button` 和所有新组件的文字标签都沿用 RFC 0001 的插值规则。

复选框与滑块在 Tab 顺序中按源码出现次序获得焦点。空格切换复选框；滑块获得焦点后，左右方向键按步长调节。两者都向辅助技术提供解析后的标签、角色和当前值，滑块额外提供上下界。容器和分隔线不占用键盘焦点。

## 3. 类型规则与状态更新

建议首版按示例顺序解析命名参数。绑定位置只能填写一个已声明的状态名；字面量、插值字符串和算术表达式均应在该参数处报错。编译器检查绑定类型、缺失或重复参数，以及 `min < max`。例如 `Checkbox("Mute", checked: volume)` 应报告“checked 需要 bool，volume 为 i32”，并保留源码行列。

WASM 实例中的状态是唯一数据来源。首次显示控件和重绘都只读状态。用户操作产生带类型的写入事件；按钮继续调用现有处理器。宿主在本次控件遍历后按事件顺序提交写入，再请求重绘。因此，按钮重置状态后，标签、复选框和滑块会在下一帧显示同一组值。

滑块范围只约束这个控件的输入。若按钮把 `volume` 设为 150，绑定文本显示 150，滑块手柄停在上界；单纯绘制不得将状态改回 100。下一次用户拖动或按键时，滑块提交范围内的整数。两个绑定同一状态的滑块可以有不同范围。

## 4. 两个仓库怎样实施

**Solia 编译器。** 将现有平铺控件列表改为有类型的视图树。容器持有子节点，展示节点持有已解析的标签片段，输入节点持有已解析的状态槽和参数。按钮处理器仍按源码顺序编号。解析与包加载阶段统一限制树深（建议上限 32，根深度为 1）与节点总数（建议上限 4096，含根节点），在递归或分配超限前给出诊断。

**Solia 宿主。** 在现有 `AppInstance::render` 中递归绘制节点。用容器路径和子节点序号生成稳定控件 ID，使相同标签的控件也能分别获得焦点；实例被替换时重建 ID 命名空间。输入事件只能写入该节点绑定且已校验的可变 WASM 全局槽。布尔写入编码为 0 或 1，滑块写入在宿主事件边界校验范围。egui 使用的临时编辑值只在用户实际操作时提交。

**Solia Browser。** 延续现有下载、编译和嵌入接口。部署示例时，在现有测试源站增加明确的 `/settings.solia` 资源；当前源站仅挂载了 Counter 文件。Browser 的验证重点是地址栏与应用间的焦点切换、窄窗口布局和重载时的状态重置。

## 5. 包兼容策略

建议新版加载器同时识别 SAPP v1 和 v2。v1 的 `gap + widgets` 在解码时转换成一个根列，沿用原有按钮 ABI。编译器遇到可由 v1 完整表示的程序继续输出 v1；出现新控件、根行或嵌套布局时输出 v2。这样现有 Counter 源码仍能构建出旧宿主可运行的包。

v2 清单保存根节点和类型化绑定。加载器在打开窗口前验证每个状态和处理器引用、状态类型、绑定槽的 WASM 类型与可变性、滑块范围及树规模。旧宿主按版本号明确拒绝 v2。远程 `.solia` 由客户端自带的编译器处理，因此要打开新示例，Browser 也需要包含新版 Solia 库。

## 6. 交付顺序与验收

| 阶段 | 交付 | 验收场景 |
| --- | --- | --- |
| 布局与展示 | 视图树、v1/v2、嵌套行列、标题与分隔线 | 用升级前生成的 v1 Counter 包点击加一；新设置页缩窄时行内控件换行；越界树深得到诊断 |
| 表单交互 | 复选框、整数滑块、键盘交互、绑定校验 | 初始值为 false 和 40；勾选并调至 65 后文本同步；Reset 恢复两个初值；错误类型在编译时即被拒绝 |
| 网络联验 | 发布设置示例，用同一份源码运行 CLI 与 Browser | 通过 HTTPS 打开后用鼠标和键盘完成上述操作；重载恢复初值；两个同名控件各自保持焦点与绑定 |

文本输入框是下一批组件的首选。它需要先定义可变 `String` 状态、UTF-8 在 WASM 与宿主间的传递，以及输入法组合文本何时提交。图片组件另需确定资源 URL 如何解析、由谁下载以及大小限制；这两项分别适合独立 RFC。
